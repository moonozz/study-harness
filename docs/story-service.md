# 서비스 스토리 정리

## 유저스토리

| 구분 | 내용 |
| --- | --- |
| 유저스토리 1 | 서비스 사용자가 카테고리와 태그 후보 목록을 미리 만들어 저장 후보의 분류 기준으로 사용한다. |
| 유저스토리 2 | 서비스 사용자가 게시물 링크나 본문을 입력해 서비스별 이름·설명·URL·카테고리·태그 후보를 추출한다. |
| 유저스토리 3 | 서비스 사용자가 추출 근거를 보고 저장 후보의 정보와 미리 기입된 카테고리·태그가 적절한지 확인한다. |
| 유저스토리 4 | 서비스 사용자가 적절하지 않은 저장 후보의 이름·설명·URL·카테고리·태그를 수정하거나 제외한다. |
| 유저스토리 5 | 서비스 사용자가 확정한 후보를 저장하고 검색·필터로 필요한 서비스를 다시 찾는다. |

## PRD에 명시된 초기 카테고리

| 카테고리 | 포함할 용도의 예 |
| --- | --- |
| 디자인·프로토타이핑 | UI 디자인, 디자인 시스템, 화면 설계 |
| 개발·배포 | 코드 작성, 테스트, 웹사이트 구축, 호스팅 |
| 자동화·연동 | 반복 업무 자동화, 앱 연결, 워크플로 |
| 콘텐츠 제작 | 이미지·영상·음성·글 제작 |
| 생산성·협업 | 문서, 메모, 일정, 팀 협업 |
| 리서치·데이터 | 정보 탐색, 자료 분석, 데이터 시각화 |
| 미분류 | 용도가 불명확하거나 기존 분류에 맞지 않는 경우 |

## 이 서비스에서 어기면 안 되는 것

| 구분 | 내용 |
| --- | --- |
| 원칙 1 | 자동 분류는 기존 카테고리를 사용하고 새 카테고리를 임의로 생성하지 않는다. |
| 원칙 2 | 확인되지 않은 설명·URL을 사실처럼 채우지 않는다. |
