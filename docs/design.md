# 나만의 서비스 아카이브 — Design System

- 버전: v0.1
- 작성일: 2026-10-11
- 기준 문서: 나만의_서비스_아카이브_PRD.md
- 적용 범위: 개인용 반응형 웹서비스 MVP

## Overview

나만의 서비스 아카이브는 게시물 링크에서 소개된 서비스의 이름·설명·URL을 추출하고, 카테고리별로 저장해 필요할 때 다시 찾는 개인 라이브러리다.

화면은 **링크 입력 → 추출 결과 확인 → 선택 저장 → 검색 → 서비스 사용**의 흐름을 보여준다. 게시물은 출처로 남기고 개별 서비스를 카드로 정리한다. 자동 추출된 정보는 사용자가 근거를 확인하고 수정한 뒤 저장한다.

흰 캔버스와 짙은 검정 텍스트의 모노크롬을 기본으로 한다. 그림자 대신 중립색 배경과 얇은 경계선으로 영역을 구분한다. 버튼·필터·배지는 필 형태, 카드·입력은 둥근 사각형을 사용한다. 서비스 로고의 원래 색상은 유지할 수 있지만 로고 수집은 MVP 필수 기능이 아니다.

파란색 액센트는 **사용자가 확인해야 할 추출 정보**에 제한적으로 사용한다. 주요 CTA는 검정이다. 상태는 색상과 함께 아이콘·텍스트로 설명한다.

**Key Characteristics**

- 서비스 정보를 빠르게 읽는 모노크롬 작업 공간.
- 서비스별 독립 카드와 카테고리·태그 중심 탐색.
- 자동 추출값·사용자 수정값·원문 근거의 구분.
- URL 누락·중복·접근 제한·부분 저장의 명확한 표현.
- PC에서 정리하고 모바일에서도 저장·검색 가능한 반응형 웹.

## Colors

토큰 표기 `{colors.*}`는 디자인·구현 간 참조 규칙이다. 구현 시 CSS 변수나 테마 토큰으로 매핑한다.

### Brand & Accent

| Token | Value | Use |
| --- | --- | --- |
| `{colors.primary}` | #141414 | 주요 CTA·활성 필터 |
| `{colors.ink}` | #141414 | 제목·본문·주요 아이콘 |
| `{colors.on-primary}` | #ffffff | 검정 버튼 위 텍스트 |
| `{colors.accent}` | #0066ff | 확인 필요 아이콘·경계 |
| `{colors.accent-soft}` | #edf4ff | 확인 필요 배경 |
| `{colors.accent-ink}` | #004fc4 | 연한 파랑 위 상태 텍스트 |

primary와 ink는 값이 같지만 행동과 텍스트라는 의미를 구분한다. 파란색을 장식·가격·카테고리 구분에 사용하지 않는다.

### Surface & Border

| Token | Value | Use |
| --- | --- | --- |
| `{colors.canvas}` | #ffffff | 페이지·기본 카드·모달 |
| `{colors.canvas-soft}` | #f3f3f3 | 툴바·필터·선택 배경 |
| `{colors.field}` | #f0f0f0 | 입력·텍스트 영역 |
| `{colors.hairline-soft}` | #e8e8e8 | 비대화형 구획의 보조 경계 |
| `{colors.hairline}` | #d0d0d0 | 카드·외곽선 버튼의 보조 경계 |
| `{colors.control-border}` | #707070 | 체크박스 등 식별에 필요한 경계 |
| `{colors.scrim}` | rgba(20, 20, 20, 0.40) | 모달 뒤 배경 |

연한 경계선만으로 클릭 가능 영역이나 선택을 구분하지 않는다. 식별이 필요한 컨트롤에는 명확한 라벨·아이콘·채움·경계를 함께 사용한다.

### Text

| Token | Value | Use |
| --- | --- | --- |
| `{colors.ink-soft}` | #262626 | 보조 제목 |
| `{colors.text-muted}` | #666666 | 설명·출처·날짜·placeholder |
| `{colors.text-faint}` | #adadad | 비활성·장식 요소만 |

필수 안내·오류·날짜·입력 예시에는 text-faint를 쓰지 않는다. Placeholder는 입력 라벨을 대체하지 않는다.

### Semantic States

| State | Treatment | Example |
| --- | --- | --- |
| 성공 | 체크 아이콘·중립색 | 저장 완료 |
| 확인 필요 | 파란 아이콘·배경·구체적인 라벨 | URL 확인 필요 |
| 실패 | 경고 아이콘·짙은 텍스트·해결 행동 | 내용을 가져올 수 없어요 |
| 처리 중 | 진행 아이콘·단계명 | 서비스를 정리하는 중 |
| 중복 후보 | 연결 아이콘·비교 정보 | 기존 서비스와 중복 가능 |

색상만으로 상태를 전달하지 않는다. 원문에서 발견한 링크를 공식 URL 검증 완료로 표현하지 않는다.

## Typography

### Font Family

Pretendard를 한글·영문 공통 글꼴로 사용한다. 웹에서는 Variable, Figma에서는 Regular 400 · SemiBold 600 · Bold 700을 사용한다. Light 300은 큰 소개 문장에만 선택적으로 사용한다.

Fallback: `-apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Noto Sans KR", sans-serif`.

### Hierarchy

| Token | Size | Weight | Line Height | Use |
| --- | --- | --- | --- | --- |
| `{typography.display}` | 32px | 700 | 1.3 | 첫 방문 소개 |
| `{typography.heading-1}` | 28px | 700 | 1.3 | 화면 제목 |
| `{typography.heading-2}` | 24px | 700 | 1.35 | 구역 제목 |
| `{typography.heading-3}` | 20px | 700 | 1.35 | 상세·모달 제목 |
| `{typography.heading-4}` | 18px | 700 | 1.35 | 카드 서비스명 |
| `{typography.title}` | 17px | 600 | 1.4 | 강조 행 |
| `{typography.body-lg}` | 17px | 400 | 1.5 | 화면 소개 |
| `{typography.body}` | 15px | 400 | 1.5 | 설명·메모 |
| `{typography.body-sm}` | 13px | 400 | 1.5 | 근거·출처 |
| `{typography.link}` | 15px | 600 | 1.5 | 버튼·내비게이션 |
| `{typography.label}` | 12px | 600 | 1.4 | 배지·태그 |
| `{typography.caption}` | 12px | 400 | 1.5 | 보조 메타데이터 |

자간은 0을 기본으로 한다. 긴 URL·영문 이름은 줄바꿈하며 상세·편집에서는 전체 내용을 볼 수 있어야 한다. 모바일 입력 텍스트는 16px 이상을 사용한다.

## Layout

### Spacing System

- 8px 기준, 4px 보조 간격.
- `{spacing.xxs}` 4px · `{spacing.xs}` 8px · `{spacing.sm}` 12px · `{spacing.md}` 16px.
- `{spacing.lg}` 24px · `{spacing.xl}` 32px · `{spacing.section}` 48px · `{spacing.section-lg}` 64px.
- 카드 내부: PC 24px, 모바일 16px. 목록 간격: 16~24px.
- 큰 여백은 화면 구획에 사용하며 검토 목록은 일정한 간격으로 밀도 있게 배치한다.

### Grid & Container

- PC 콘텐츠 최대 폭 1200px, 가운데 정렬.
- 아카이브는 제목·추가 버튼 / 검색·필터·정렬 / 결과 수 / 카드 순서로 구성한다.
- 링크 입력 폼은 최대 폭 720px의 단일 열.
- 검토 화면은 편집 가능한 단일 열 후보 목록. 넓은 화면에서는 근거를 카드 오른쪽에 배치할 수 있다.
- 상세는 넓은 화면에서 핵심 정보와 출처·메모의 2열, 모바일은 단일 열.
- 카테고리 관리는 목록과 추가·편집 폼으로 구성한다.

### Responsive Strategy

| Range | Reference Frame | Behavior |
| --- | --- | --- |
| 360~767px | 390 × 844 | 여백 16px·카드 1열 |
| 768~1023px | 834 × 1112 | 여백 24px·카드 2열 |
| 1024px 이상 | 1440 × 900 | 여백 32px·최대 폭 1200px·카드 3열 |

- 360px에서도 페이지 가로 스크롤이 생기지 않아야 한다.
- 긴 URL은 `overflow-wrap: anywhere` 등으로 줄바꿈한다.
- 버튼·아이콘 버튼의 조작 영역은 최소 44 × 44px.
- 모바일 하단 저장 영역은 고정 가능하나 키보드·안전 영역을 고려해 입력과 마지막 카드를 가리지 않는다.
- 필터는 줄바꿈·펼치기를 제공하며 조작을 가로 스크롤 안에만 숨기지 않는다.
- 모바일에서도 카테고리 관리·출처·편집 기능에 접근할 수 있다.

### Image Behavior

- 서비스 아이콘: 카드 40px, 상세 64px. 원본 비율을 유지하고 contain으로 표시한다.
- 로고가 없거나 실패하면 이니셜 또는 공통 서비스 아이콘으로 대체한다.
- 이미지 유무가 카드의 핵심 정보 배치를 바꾸지 않게 한다.
- 자동 스크린샷 생성은 MVP 필수 기능이 아니다.
- 홍보 배너·자동 재생 마키·장식 사진을 작업 영역에 두지 않는다.

## Elevation & Depth

| Level | Treatment | Use |
| --- | --- | --- |
| 0 | 흰 배경 | 페이지 |
| 1 | 중립색 채움 | 툴바·근거 영역 |
| 2 | 흰 배경·얇은 경계 | 카드·모달 |
| Selected | 회색 채움·짙은 경계·체크 | 선택 후보 |
| Review | 연한 파랑·확인 필요 라벨 | 검토할 정보 |
| Overlay | scrim·흰 표면 | 확인 대화상자 |

그림자·장식용 그라디언트는 사용하지 않는다. 세그먼트·모달·토스트도 채움·경계·위치로 구분한다. 큰 검정 푸터 대신 필요할 때 작은 보조 정보 행을 둔다.

## Shapes

| Token | Value | Use |
| --- | --- | --- |
| `{rounded.none}` | 0px | 구분선 |
| `{rounded.xs}` | 8px | 체크박스·작은 내부 영역 |
| `{rounded.sm}` | 16px | 입력·텍스트 영역·근거 패널 |
| `{rounded.md}` | 24px | 서비스 카드·후보·모달 |
| `{rounded.full}` | 9999px | 버튼·필터·태그·배지·세그먼트 |

필 형태는 작은 행동·선택 요소에 적용한다. 여러 줄 입력과 큰 콘텐츠는 둥근 사각형을 사용한다. 서비스 아이콘 타일은 30% 모서리 반경으로 통일한다.

## Components

### Buttons

| Component | Style | Labels |
| --- | --- | --- |
| `button-primary` | 검정·흰 텍스트·필·48px 높이 | 서비스 추출하기, 선택한 3개 저장, 서비스 열기 |
| `button-outline` | 흰 배경·경계·필·48px 높이 | 직접 등록, 본문 붙여 넣기, 취소 |
| `button-pill-soft` | 연한 회색·필·44px 높이 | 원본 게시물 보기, 필터 초기화 |
| `icon-button` | 최소 44px 조작 영역 | 즐겨찾기, 더 보기, 닫기 |

작업 구역별 주요 CTA는 원칙적으로 1개다. 처리 중 상태를 표시하고 중복 제출을 막는다. 비활성 이유는 주변 안내로 설명한다. 삭제는 대상 이름을 명시하고 확인 대화상자에서 확정한다. 외부 링크에는 새 창 안내를 제공한다.

### Service Card — `service-card`

- 흰 배경·얇은 경계·24px 모서리.
- 순서: 아이콘·이름·즐겨찾기 → 설명 → 카테고리·태그 → 확인 상태·보조 정보.
- 이름 최대 2줄, 설명 최대 3줄. 상세에서 전체 내용을 보여준다.
- 이름 링크로 상세를 열고 즐겨찾기는 별도 버튼으로 둔다. 링크 안에 버튼을 중첩하지 않는다.
- URL이 없어도 상세 조회는 가능하며 `URL 확인 필요`를 표시한다.

### Extraction Candidate — `extraction-card`

- 상단: 선택 체크박스·서비스명·확인 필요/중복 배지.
- 본문: 이름·설명·URL·카테고리·태그 편집 필드.
- 하단: 짧은 추출 근거·원본 링크. 긴 근거는 접기/펼치기를 제공한다.
- 자동 제안은 `자동 추출` / `자동 분류`, 사용자 수정은 `수정됨`으로 구분한다.
- URL 누락 안내: `원문에서 서비스 URL을 찾지 못했어요. 나중에 추가할 수 있어요.`
- 선택은 체크·경계·배경으로 표현한다. 선택 제외와 삭제를 구분한다.
- 저장된 후보는 완료 표시와 상세 링크를 제공한다. 실패 후보는 입력과 재시도 행동을 유지한다.

### Search & Filters

- `search-input`: 보이는 라벨·검색 아이콘·지우기. 안내: `서비스명, 용도, 태그, 메모로 검색`.
- `filter-chip`: 기본 연한 회색, 활성 검정·흰 텍스트.
- `segmented-control`: 전체 / 즐겨찾기. 활성은 흰 채움·짙은 경계, 그림자 없음.
- `sort-select`: 최근 저장순 / 이름순.
- 적용 필터·결과 수·초기화를 제공한다. 검색과 필터는 함께 적용한다.
- 카드의 읽기 전용 태그와 툴바의 조작 가능한 필터를 구분한다.

### Inputs & Forms

- `text-input`: 회색 채움·16px 모서리·상하 12px/좌우 16px 여백.
- `text-area`: 설명·본문·메모. 여러 줄 입력과 높이 조절 가능.
- `category-select`: 기존 목록과 미분류.
- `tag-editor`: 추가·제거 가능한 필 태그. 제거 버튼에 태그 이름 포함.
- 보이는 라벨·필수/선택 표시·필드 가까운 오류를 제공한다.
- URL 입력의 자동 대문자·철자 교정을 끄고 적절한 입력 모드를 사용한다.
- 오류가 나도 입력값을 유지한다. 이름·설명은 필수, URL은 선택이다.

### Navigation — `app-header`

서비스명·내 아카이브·카테고리 관리·링크 추가를 배치한다. 헤더 외곽은 연한 회색 필 형태를 사용할 수 있다. 모바일은 서비스명·링크 추가를 우선 표시하고 나머지는 접근 가능한 메뉴로 제공한다.

현재 위치와 뒤로 가기를 표시하고, 이동 시 검토 중 편집값을 보존한다. 고정 헤더는 본문과 포커스된 항목을 가리지 않는다.

### Source & Duplicate Review

- `source-panel`: 게시물 제목·출처 URL·저장일·짧은 근거. 서비스 URL과 명확히 구분한다.
- `duplicate-panel`: 기존 정보 비교와 `기존 서비스에 출처 추가` / `별도 서비스로 저장`.
- 이름만 같은 후보는 중복 가능성으로 표시한다. 자동 병합된 것으로 표현하지 않는다.
- 기존 서비스의 설명·메모가 출처 추가로 덮어쓰이지 않는 흐름을 제공한다.

### Status & Feedback

- `status-badge`: 처리 중·검토 가능·URL 확인 필요·일부 저장·저장 완료.
- `progress-panel`: 현재 단계와 다음 행동. 실제 측정하지 않은 진행률은 만들지 않는다.
- `inline-alert`: 실패 이유와 본문 붙여 넣기·재시도.
- `toast`: 짧은 완료 알림. 항목별 저장 결과는 화면에 지속 표시한다.
- `skeleton-card`: 로딩 중 배치 유지. 서비스 0개 결과와 구분한다.

### Empty States

| State | Message | Action |
| --- | --- | --- |
| 최초 아카이브 | 아직 저장한 서비스가 없어요 | 첫 링크 추가 |
| 검색 결과 없음 | 검색 조건에 맞는 서비스가 없어요 | 필터 초기화 |
| 추출 결과 없음 | 본문에서 소개된 서비스를 찾지 못했어요 | 직접 등록 / 본문 다시 입력 |
| 접근 제한 | 이 게시물의 내용을 가져올 수 없어요 | 본문 붙여 넣기 |
| URL 누락 | 서비스 URL을 확인해 주세요 | URL 편집; 저장은 가능 |

간단한 아이콘·설명·다음 행동으로 구성한다. 장식 이미지가 주요 행동을 밀어내지 않게 한다.

### Category Management — `category-row`

카테고리명·서비스 수·이름 변경·삭제를 제공한다. 삭제 확인에는 `연결된 서비스는 미분류로 이동해요`를 안내한다. 기본 미분류는 삭제할 수 없다. 카테고리별 색상은 배정하지 않는다.

### Modal & Auth

- `modal-card`: 흰 배경·24px 모서리·경계·scrim, 그림자 없음.
- 제목·본문·확인·취소 순서. 모바일에서는 화면 폭에 맞춘다.
- 모달 진입 시 포커스를 이동하고 닫을 때 호출 버튼으로 돌려준다.
- `auth-form-card`: 외부 접근 가능한 배포에서 개인 데이터 보호를 위한 진입 화면. 로그인 방식은 구현 단계에서 정한다.

## Screen Composition

| Screen | Main Structure | Primary Action |
| --- | --- | --- |
| 내 아카이브 | 제목·서비스 수 / 검색·필터 / 카드 그리드 | 링크 추가 |
| 링크 추가 | URL / 본문 붙여 넣기·직접 등록 / 처리 상태 | 서비스 추출하기 |
| 추출 결과 확인 | 발견 수·선택 수 / 후보 목록 / 저장 결과 | 선택한 N개 저장 |
| 서비스 상세 | 이름·설명 / URL·분류 / 메모 / 출처 | 서비스 열기 |
| 카테고리 관리 | 분류 목록·서비스 수 / 추가·수정 | 카테고리 추가 |

입력과 검토는 하나의 작업으로 이어진다. 저장 후 아카이브에서 방금 저장한 서비스를 확인할 수 있어야 한다. URL이 없는 상세에서는 `URL 추가`를 우선 행동으로 제공한다.

## Interaction & Accessibility

- 탭 순서는 읽기 순서와 일치시킨다.
- 포커스는 2px 검정 외곽선과 2px 간격. 검정 표면 위에서는 흰 안쪽 경계를 함께 사용한다.
- 체크박스·메뉴·모달·필터를 키보드로 조작할 수 있게 하고 상태·펼침 여부를 보조 기술에 전달한다.
- 진행 상태·저장 완료는 적절한 live region으로 알린다.
- 일반 텍스트 대비 4.5:1, 큰 텍스트와 필요한 UI 식별 요소 3:1 이상을 실제 조합에서 검증한다.
- Hover만으로 편집·삭제·출처를 노출하지 않는다.
- 모션은 150~200ms 내외의 상태 전환 보조로 제한하고 reduced motion을 존중한다.
- 확인 필요·실패·중복은 색 없이도 이해 가능해야 한다.

## Do's and Don'ts

### Do

- 이름·설명·URL·분류를 서비스 정보의 중심에 둔다.
- 게시물 하나의 여러 서비스를 독립된 후보와 카드로 표현한다.
- 검정 CTA·필 버튼·중립 표면·얇은 경계를 일관되게 사용한다.
- 파란색은 확인 필요 표시와 해당 안내에만 사용한다.
- 서비스 URL과 원본 출처를 구분하고 근거를 쉽게 확인하게 한다.
- 누락 정보는 보완 가능하게 표시하고 자동 제안과 수정값을 구분한다.
- PC·모바일 모두 검색·저장·수정 흐름을 완성한다.
- 이미지 없이도 읽기 쉬운 카드를 만든다.

### Don't

- 요금제·수상·학습 미션·판매 자산·커뮤니티를 MVP 화면에 포함하지 않는다.
- URL을 추측하거나 추출 결과를 검증 완료처럼 표시하지 않는다.
- 카테고리별 색상·그라디언트·그림자·홍보 마키를 추가하지 않는다.
- 카드 링크 안에 즐겨찾기·삭제 버튼을 중첩하지 않는다.
- 토스트만으로 저장 결과를 전달하거나 부분 실패를 숨기지 않는다.
- 긴 이름·URL의 전체 값을 확인할 방법을 없애지 않는다.
- 연한 텍스트·색상만으로 오류·선택·필수 정보를 전달하지 않는다.
- 확인되지 않은 가격·평점·무료 여부를 서비스 카드에 추가하지 않는다.
